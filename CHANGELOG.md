## 0.15.0
- Opt-in: everything below applies only with the new optional profile field `tdd: yes` (`no` default; an invalid value is a `profile gap`). `decide-triage.mjs` prints `tdd: yes|no` and the `triage` event records `tdd: true` (sticky per topic), so the audit reads the setting from the ledger, not the profile. Without it, coders and reviewers name and run proof tests as before and the audit applies neither rule: existing projects and ledgers audit exactly as in 0.14.0. `test_first_commit` means something only with `tdd: yes`; `profile.mjs` warns otherwise.
- TDD evidence, two new `/decide` rules (`/decide` 1.4.0, operator 1.5.0, peer 1.1.0, rules 1.7.0). DEC-21 `script`: the coder's report shows each proof test and each fix-round test red, then green, as labelled lines (`RED <test> -- ` failing without the change, `GREEN <test> -- ` passing with it, run with the profile's targeted-test command), or `CANNOT FAIL FIRST <test> -- <reason>` (docs only, a pure refactor, no targeted-test command in the profile). DEC-22 `script`: the `reviewer` and `re-reviewer` revert only the production part of the diff (three-dot, from the merge-base) in a scratch worktree made with `git worktree add --detach` under `mktemp -d`, never the coder's worktree or branch, run each proved test alone with the targeted-test command (their one exception to read-only), and write `PROOF CHECK <test> -- fails|passes|not checked: <reason>|exempt`. `fails` means the test built, ran and failed; a build failure or anything that kept it from running is `not checked: <reason>`. A `CANNOT FAIL FIRST` test is exempt from the revert check; the reviewer writes `exempt` and judges the reason. A pass is a CONFIRMED finding, "proof does not prove", and blocks the merge until a later `fails` of that test (`not checked` and `exempt` never clear it). Cleanup undoes the revert and runs a plain `git worktree remove` (never `--force`; a refusal leaves the worktree and reports its path).
- `scripts/proof-check.mjs` (no model, zero dependencies): `--coder` and `--reviewer` check those lines (exit 2 with `proof gap:` lines). Names are exact and end at the first ` -- `, so pytest ids, Go subtests and jest names with colons work; `--test` repeats; `--coder --json` prints the proved and exempt tests for the ledger; `--reviewer` takes the required tests from `--coder-report` (or `--test`) and needs no line for an exempt test; the CONFIRMED finding is matched in any case and names the test exactly. `scripts/proof-revert.mjs` (read-only) prints the revert commands from `git diff --name-status -M <merge-base> <head>`: modified and deleted files restored with `git checkout <merge-base> -- <file>`, added files removed, renames handled; tested on a throwaway repo.
- Ledger kinds `coder_report` (`evidence`, `tests`, `exempt`) and `proof_check` (`result`). The audit checks DEC-21 (a review needs evidence ok since the last coder run, when that run is stamped with rules 1.7.0 or later, so a mid-session upgrade does not flag older work) and DEC-22 (every test in the `coder_report` before the review has a proof check on the reviewed head; a pass not cleared by a later `fails` blocks the merge). A rules version going backwards in a ledger is a LEDGER violation; mixed versions are a `warn:`. Scenarios take a `report` (`report.md`, and `coder.md` for a reviewer scenario); twenty-one new scenarios (`tdd-off-no-evidence-ok`, `tdd-on-requires-evidence` among them). Tests: `scripts/proof-check.test.mjs`, `scripts/proof-revert.test.mjs`, audit and profile tests.
- Optional profile field `test_first_commit` (`no` default, or `yes`: the coder commits the failing test alone before the fix and reports `TEST FIRST <test> -- <sha>`); existing profiles stay valid, triage ignores it. The profile template names the targeted single-package run as the targeted-test command. The operator's worker brief, the merge protocol and the peer skill point to DEC-21 and DEC-22.
- `tdd: auto` (owner-approved; the default stays `no`): `decide-triage.mjs --proof <test>...` decides per step with the new deterministic `scripts/tdd-suggest.mjs` (no `targeted_test`, docs or config only, no tests, or unclear: no; production code touched with a security path or one-way door, or with a named proof test: yes) and prints `tdd: yes|no (auto: <reason>)`; the triage event records it as `tdd: true/false`, and with `auto` a triage (rules 1.7.0 or later) without it is a LEDGER violation.
- Third review round: with `tdd: yes` or `auto` a rules version going backwards anywhere in the ledger is a LEDGER violation; with `auto`, the audit re-runs `tdd-suggest` on the triage files and a recorded `tdd: false` it would call yes (security path or one-way door) is a LEDGER violation, and `tdd: false` on a code-touching triage warns; `tdd: auto` without `targeted_test` is a profile gap like `yes`; the missing-command check on CANNOT FAIL FIRST reasons is narrowed to one clause about a missing test or profile command.
- Re-review fixes: a missing targeted-test command is never a `CANNOT FAIL FIRST` reason (refused by proof-check); it is the profile gap `targeted_test`, the new machine field required with `tdd: yes`. A `CANNOT FAIL FIRST` reason needs at least three words, and an all-exempt report on a step that touches production code warns (proof-check `--file`, and the audit from the triage files; `scripts/paths.mjs` classifies paths). With `tdd: yes` in the profile, a triage stamped 1.7.0 or later without `tdd: true` is a LEDGER violation. The rules-version checks apply only to `tdd: true` topics. An invalid `tdd` (`true`, `Yes`) is a profile gap in triage too. proof-revert refuses a path with a newline. The **Team** paragraph of the `/decide` core moved to `refs/decide/team-tracks.md`.
- `commands/decide.md` stays under the size limit: step 2's triage command paragraph moved to `refs/decide/team-tracks.md`, which already held the rest of step 2; its last sentence ("Load ... team-tracks.md for the table"), which pointed at that same ref, was dropped, and the core's step 2 now says to load the ref for the command, the caps and the table.
