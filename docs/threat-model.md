# Threat model: Orbit's guard

One page. What the PreToolUse guard (`hooks/guard.mjs`) protects, from whom, where the real boundary is, and what is accepted. Behaviour: README, Operator guard and Outward guard.

## Assets
| Asset | Harm |
|---|---|
| The base and protected branches (`main`, `master`, `release/*`, `origin/HEAD`'s target, the profile's `base_branch` and `protected_branches`) | unreviewed code reaches users; history rewritten |
| Published tags and releases | moved, deleted or re-created; consumers get different bits under the same version |
| CI runs | cancelled, re-run or dispatched to fake a green result or burn the owner's runners |
| The owner's approval | an agent message, ledger line or forged go state passed off as the owner's go |
| CI evidence | a commit status or check run minted by an agent to fake a green |
| The owner's `gh` token | read (`gh auth token`) and used outside every check (`curl`) |

## Actors
- **Operator**: the main thread that coordinates; must not write the repo (OPR-01).
- **Peer**: another main session working a branch.
- **Subagent worker**: a coder or reviewer started by a session; its prompts surface in the main session.
- **Injected content**: text in an issue, a PR, a file or a tool result that steers any of the above.
None of them is the owner. An agent can write the ledger and the worktree's `.agents/project.md`, so neither can grant anything (the main checkout's profile sets the review trailer and the base push grant; a worktree's only adds).

## Trust boundary
Claude Code's permission system is the boundary: its allow, ask and deny rules and the owner's answer to a prompt. The guard is a guardrail inside it: it denies destructive actions and turns shared actions into a prompt (`ask`) that only the owner can answer. Under `dontAsk` or a headless run nothing can prompt, so shared actions are denied. The profile can only add protected branches; the guard never reads the ledger.

The owner approves in two forms: an answer to a prompt, or **the go** (`/orbit:unattended`), opened with a permission prompt. `/orbit:unattended on` has the model run one fixed command, `node <plugin root>/hooks/unattended.mjs on <dur>`, and the guard answers that exact command with `ask` in every mode, `bypassPermissions` too: "open an unattended go of N minutes for this session". The proof is the owner's answer to that prompt: the model can ask for it but cannot answer it. The terminal, the IDE and Claude on the web show the same prompt, so the go works the same in each; nothing is written to a terminal and there is no code. A respelled path (quotes, escapes, `$'…'`) asks the same; no argument prints the usage; a duration out of range (0, over 24 h) is denied with the usage, no prompt. Any other command that names the script, or a word that can build it from a literal `unatt` stem, is denied, no prompt: another path, an option, an env prefix, a compound, a here-doc, a redirect, a word that names it or resolves to it, a glob that can match it (`node …/unattende?.mjs`, `ln -s …/unatt*`; for `node`, `nodejs`, `bun` and `deno` a glob whose last segment can match `unattended.mjs`), the same inside `sh -c`, `bash -c` or `eval` (an exact `on` there is denied too), a `find` running one of those four by `-exec`, `-execdir`, `-ok` (also behind `timeout`, `env`, `nice`, `command` or `xargs`) or into `xargs` unless its only test is a `-name` that cannot match the script (any `-o`, `-or`, `,`, `!`, `-not`, `-prune`, `-path` or `-regex` counts as a test that can), and a command the guard cannot parse (line continuations removed, `$'…'` escapes decoded, quotes and backslashes removed) that has `node`, `nodejs`, `bun` or `deno` and names the plugin's `hooks` folder (the segment `hooks` as a path part: `/hooks/`, `hooks/`, `cd hooks`), contains `unatt`, or runs with its cwd inside the hooks folder, which is denied too, with no stem, token or glob matching on that text (extglob alternatives and split stems such as `@(zz|u*).mjs` or `una$"tt"ended.mjs` fall under it). The cost: an unparsable command that mentions `hooks` and a runtime is denied (`a=(1); node --check hooks/guard.mjs`), and so is one that names `unatt` (`a=(1); node --test scripts/unattended.test.mjs`); the same commands parsable are not. An unparsable command with a runtime word is also denied when a script word (`.mjs`, `.js`, `.cjs`, not `*.test.*`) holds a glob character or an expansion (`a=(1); node R/h?oks/u*.mjs`), whatever it spells; a parsable runtime command whose script name holds an expansion that can spell `unattended.mjs` (`una$()ttended.mjs`, `u$"n"attended.mjs`) is denied too, never asked. Any command that sets `nocaseglob` and has a runtime word is denied, because case-insensitive globbing changes what a glob matches (`shopt -s nocaseglob; node …/U*.MJS`). A glob that cannot match (`node --test scripts/*.test.mjs`) or a variable operand (`node "${CLAUDE_PLUGIN_ROOT}/scripts/ledger.mjs"`) is not the go's command. Not seen: a shell that reads its script from stdin (`echo '…unattende?.mjs…' | bash`, a here-string or here-doc to `bash` or `sh`, `source <(…)`), a name held in a variable, `node -e`/`--eval` importing a built name, another interpreter, a program the model writes first, or a copy of the hooks folder run under another name; such a program can write the go file, so the go is intent and the evidence gates carry the safety. The proof relies on Claude Code prompting for a hook `ask` in every mode on every surface, as the shared-action asks do; the session comes from `CLAUDE_CODE_SESSION_ID` in the Bash environment (unset: no go opens). The go is interpreter-forgeable (a program the agent runs can write its state file), so it is intent, not proof: it counts only for its session's main thread in `bypassPermissions`, at most 24 h, and allows only two actions, each bounded by evidence the guard reads itself from the URL the push uses (origin's push URL must equal its fetch URL): the pinned merge sha's parents, tree, the main checkout profile's trailer and paths in git; a base equal to `origin/HEAD` and the profile's `base_branch`; a green base tip and first-attempt green GitHub Actions runs covering its workflows and the profile's `required_checks`; a branch delete only once merged. The evidence calls are killed with their process group at a 6 s deadline, and a guard timeout blocks the call. Every other shared action under it is denied. The guard denies writes to `~/.claude` (also through a dangling symlink, each hop resolved against the link's real directory, or a link made to it, its relative target resolved against the link's directory), `git remote` changes outside a prompt, status and check run writes, and scheduled or sent `/orbit:unattended` in every mode. The audit takes a go base push as the owner's only from the hook-written go log under the OS user's `~/.claude` (not `HOME`; another `--go-log` is named in the report), never from a ledger line alone.

## Accepted risks
- Not covered: git hook files that push, scripts and interpreters running a file, `make` and `npm run`, `curl` or another client with a token, non-GitHub MCP servers, shell state persisting across calls, a `node` shadowed on `PATH`.
- Node missing: the hook is silent (fail-open), except with `ORBIT_ROLE=operator`.
- The owner's `!` commands skip the hook and are not captured in the ledger.
- The owner may approve a prompt without reading it; the reason is short and fixed-shape to make that less likely, never suppressed.
- A night merge under the go is proven by CI as the agent left it, not by a reviewer: the review trailer is agent text, and changes to `scripts/**` or weakened tests outside the guard's path and skip checks pass if CI passes. An empty commit re-run to get a first-attempt green shows in the night log.
- The go state and the go log can be forged by a program the agent writes and runs (a script file or a compiled tool), or by the script reached through a variable, another interpreter or a shell reading its script from stdin (`| bash`, a here-string, `source <(…)`) (the guard asks or denies only the forms it parses); the evidence gates hold either way, the audit's DEC-06 grant does not.
- The audit reads the go log under the OS user's home while capture writes it under `HOME`: a `HOME` override makes go pushes report as violations (fails safe).
- A glob in a write target or a link or copy operand is denied only when its literal pattern, resolved against the cwd segment by segment, can match under `~/.claude`; a form the matcher does not model exactly (a POSIX class, equivalence or collating form in a set, `~` in the pattern, a `{a..b}` sequence, an unclosed `{`) is shared; any other glob is silent, so one that reaches it through another symlink (or a `..` after a symlinked segment) is not caught. An extglob form, or any glob on a line with `shopt`, `BASHOPTS` or a program the guard cannot read, is shared; an extglob group holding an expansion, a quote or an escape is a parse error.
- A claude.ai (portal) install drops `onFailure: block` from `hooks.json` (a schema warning): a hard crash or a timeout of the guard fails open there; its own errors still deny or share (`hookMain`).
